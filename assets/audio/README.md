# assets/audio

Every file in `ambient/` and `soundscapes/` is **synthesized locally** by a
script in `scripts/`, not sampled from anyone's recording. `guide/` is the
exception: spoken lines rendered by an open-weight text-to-speech model (see below). That is partly a licensing decision — there
is no attribution or redistribution term attached to any of it — and partly a
practical one: a synthesized loop can be made *exactly* periodic, which a
field recording cannot.

Both directories are 16-bit mono PCM WAV at 22.05 kHz. WAV rather than Ogg
because iOS's AVFoundation (what `expo-audio` uses underneath) does not
reliably decode Vorbis; WAV plays everywhere. 22.05 kHz halves the file size
against 44.1 kHz and is plenty for a pad, a bell, or rain.

Both generators use a fixed RNG seed, so regenerating produces the same files
rather than quietly different ones.

## `ambient/` — the activity player's music beds

Four pieces that can loop under a guided exercise. Catalogue:
`src/modules/activities/music.ts`; playback:
`src/modules/activities/ambientAudio.ts`; the user's choice is persisted by
`soundSettings.ts`.

| File | Title | Character |
| --- | --- | --- |
| `warm-pad.wav` | Warm pad | low strings and a soft bell — the default |
| `moonlight.wav` | Moonlight | darker and slower, for evenings |
| `first-light.wav` | First light | brighter and open, the one that isn't melancholy |
| `deep-rest.wav` | Deep rest | almost a drone, barely there |

30 s each, ~1.3 MB. Generated by `python3 scripts/gen-ambient-beds.py`.

Each is a sustained chord of rolled-off partial series (every voice doubled a
few cents apart so the copies beat against each other), a quiet lowpassed
noise "air" layer underneath, and a wandering pentatonic bell line on top. The
bells are what make these listenable rather than merely inoffensive: a chord
that never moves is a drone, and a drone is what people turn off.

This replaced a single hardcoded `ambient-loop.wav` — a static six-voice sine
chord with nothing happening in it. It was seamless, correctly quiet, sounded
like a test tone, and was the only option on offer.

## `soundscapes/` — the Discover tab's sound library

Six loops a user can put on independently of any exercise. Catalogue:
`src/modules/sounds/config.ts`; playback: `src/modules/sounds/player.ts`, an
app-wide singleton so a sound keeps playing after you leave the screen that
started it.

`rain` · `forest` · `summer-night` · `ocean` · `fireplace` · `stream`

20 s each, ~0.9 MB. Generated by `python3 scripts/gen-soundscapes.py`.

## `guide/` — the activity player's spoken guide

One AAC clip per guide line, all in one gentle female voice: every
activity's intro, each phase cue, and the closing line. They replaced the
phone's built-in synthesizer, which is what made the guide sound robotic; the
guide no longer uses it at all, so a line with no clip is silent. Scripts:
`src/modules/activities/config.ts`; playback: `voiceGuide.ts`; manifest:
`guideClips.ts` (generated).

Generated by `npx tsx scripts/gen-guide-voice.ts` with
[Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M) (Apache-2.0 weights)
through `kokoro-onnx`, running on this machine: no API key, no quota. The voice
is `GUIDE_CLIP_VOICE` in `guideVoice.ts`. Edge silence is trimmed so a cue
starts on its beat. Files are named by a hash of the voice and the text, so
**after editing any spoken line, re-run the script**: it records only what
changed and deletes clips nothing uses. `scripts/selfcheck-activities.ts`
fails until you do.

One-time setup (the model is ~340 MB, kept outside the repo):

```sh
mkdir -p ~/.cache/moodsense-tts && cd ~/.cache/moodsense-tts
curl -LO https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.onnx
curl -LO https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin
python3 -m venv venv && venv/bin/pip install kokoro-onnx
```

AAC rather than WAV here because speech compresses ~7x with no audible loss;
iOS and Android both decode AAC natively.

## Why they loop cleanly

Noise is built in the frequency domain on bins that are whole multiples of
1/`LOOP_SEC` — an inverse real FFT of a random-phase spectrum is periodic by
construction. Every partial frequency, chirp and LFO rate is snapped to a
whole number of cycles per loop. Anything that inherently can't be periodic (a
bell note, a raindrop landing at a random time) is mixed in modulo the loop
length, so a tail running past the end continues at the start.

The file's last sample is therefore one ordinary step away from its first — no
click, no seam, no crossfade needed.

`scripts/selfcheck-discover.ts` asserts exactly that, along with the files
being present, wired up, and audible: the first-to-last sample step must not
exceed the largest step found anywhere inside the file. A silent or clicking
loop is the failure mode that ships quietly and only shows up in someone's
ears.

(The self-check reads the asset paths out of the source rather than importing
`sounds/config.ts` or `activities/music.ts`, because their `require`d `.wav`
assets only resolve through Metro.)
